# Modelo inicial de amenazas de producción

**Estado:** baseline para G1-SEC; no certifica aislamiento ni es auditoría de penetración.

El contrato lógico de flujos, egress y pruebas cloud-neutral está en [network-boundary-contract.md](network-boundary-contract.md). Describe requisitos; no acredita que existan reglas o endpoints reales.

## Activos y límites de confianza

- URL/mensaje enviado, cuenta/credenciales, refresh tokens, historial, resultados/capturas y claves de proveedores.
- El móvil solo confía en API autenticada; API es la autoridad para identidad, cuota, propiedad e historial.
- Sandbox procesa páginas adversariales y no debe ser accesible desde Internet ni tener acceso a Mongo/API internos; solo recibe solicitudes de la API por una red/identidad privada.
- La página visitada puede controlar redirecciones, DNS y subrecursos y debe considerarse hostil incluso con validación preflight.

## Hallazgos de código a resolver antes de producción

- Chromium se lanza con `chromiumSandbox: true`; el smoke del contenedor no-root pasa localmente con el perfil seccomp oficial Playwright fijado por hash, `SYS_CHROOT` como única capacidad añadida, filesystem read-only y red desconectada (ADR-0010). El runtime productivo aún debe verificar user namespaces/seccomp/AppArmor efectivos en staging. TLS estricto: `ignoreHTTPSErrors: false`; `ERR_CERT_*` observado en navegación principal o subrecurso entrega `inconclusive/tls_certificate_invalid` sin veredicto ni captura. No sustituye egress firewall, red privada, aislamiento de contenedor ni POC productivo.
- **Mitigación local implementada, producción no certificada:** `setImmediate` se reemplazó por polling Mongo con lease/fencing y backoff; la admisión y job quedan en una escritura. MongoDB 8.0.34 desechable valida recuperación de lease vencido y rechazo de token stale. Faltan restart real con varios procesos, staging, alarmas, capacidad global y runbook de reproceso.
- **Mitigación aplicada (parcial):** login usa limitación compartida Mongo/HMAC con respuestas 429+`Retry-After` y 503 fail-closed; migración 002 y prueba concurrente pasaron en DB desechable. Trusted proxies, secretos y carga en staging aún no están configurados/verificados.
- **Mitigación aplicada (parcial):** las nuevas entradas de análisis hasta 64 KiB se cifran con AES-256-GCM y AAD de usuario/fecha/intento; migración 003 valida envelope y startup conectado valida readiness. El TTL de 366 días desde el intento más reciente del documento diario es baseline aprobado (ADR-0008); secret manager, backup/rotación de key, retención productiva y cifrado BD/red aún requieren cerrar.
- **Mitigación aplicada (parcial):** `POST /analyze` y `GET /captures/:attemptId` ahora requieren `SANDBOX_SERVICE_TOKEN` Bearer compartido; `/health` sigue público y CORS se eliminó al no existir consumidor de navegador. El API valida la URL del Sandbox y requiere HTTPS explícito en producción, mantiene TLS estándar de Node y rechaza redirecciones para llamadas con y sin Bearer (ADR-0006). Esto no acredita terminación TLS válida en el despliegue, red privada, identidad de workload, egress ni aislamiento de Chromium; las pruebas de red siguen pendientes. Ver [ADR-0003](../decisions/ADR-0003-sandbox-service-authentication.md) y [ADR-0006](../decisions/ADR-0006-api-sandbox-transport-security.md).
- DNS se comprueba en aplicación y durante rutas de Playwright; firewall egress independiente debe bloquear CIDRs privados, metadata y plano de control para reducir DNS rebinding/TOCTOU.
- **Mitigación parcial:** pool Playwright acota cola local a `maxConcurrency * 2`, devuelve 503 con Retry-After cuando satura y deduplica por attemptId dentro de proceso. Deadline aprobado de 25 s incluye preflight DNS, espera de cola y navegación/DOM/captura; aborta el contexto y devuelve 504, y la API lo reintenta mediante el worker acotado. Prueba de Chromium local con navegación colgada verifica que no produce veredicto y cierra contexto. Faltan fairness, límites cgroup/proceso, verificación staging y aislamiento real.
- **Presupuesto local implementado, no equivalente a control egress:** el pool retiene como máximo 10 ubicaciones de redirección y agrega `redirect_evidence_truncated`. El propietario aprobó 256 requests totales por análisis: `context.route` cuenta HTTP y `context.routeWebSocket` cuenta e intercepta WebSocket; el Sandbox bloquea WebSocket porque no tiene validación SSRF/destino compatible. La solicitud 257 produce `inconclusive/resource_limit_exceeded`, cierra el contexto y no genera veredicto/captura. `request-budget.browser.ts` prueba Chromium con 256 HTTP admitidas y WebSocket 257 bloqueado, cero veredicto/captura. El test de redirección genera 127 iframes (255 requests con documento principal) para probar evidencia sin exceder presupuesto. La integración API/Mongo/worker/Sandbox/Chromium verifica el exceso HTTP y ausencia de captura. No limita bytes/CPU/memoria/disco ni demuestra firewall egress/DNS cloud.
- `ProcessAnalysisJobUseCase` usa códigos estables sin copiar errores crudos; el worker confirma terminales solo con lease token vigente. Reintentos temporales son acotados y el Sandbox cachea idempotencia local por 10 min. Esto no es idempotencia distribuida, outbox de auditoría ni cap global de jobs pendientes.
- **Proxy de captura implementado y probado localmente, pero bloqueado por configuración y red:** `GET /analyses/{attemptId}/capture` autentica y verifica propiedad antes de solicitar bytes WebP al Sandbox; la integración Mongo/API/worker/Sandbox/Chromium comprobó una captura WebP real y los bytes RIFF/WEBP por el proxy. El proxy sigue deshabilitado por defecto (`CAPTURE_PROXY_ENABLED=false`). La UI móvil lo mantiene oculto. No exponer `local://` ni el endpoint Sandbox al cliente; habilitarlo solo tras probar aislamiento privado API↔Sandbox y almacenamiento/purga en staging.
- La API antes reflejaba cualquier `Origin` y emitía `Access-Control-Allow-Credentials:true`. Se corrigió: CORS desactivado por defecto, allowlist de orígenes exactos mediante `CORS_ALLOWED_ORIGINS` y sin credenciales. Pruebas cubren preflight admin y origen hostil; aún falta fijar/probar el origen real de consola en staging. CORS no es control de autenticación ni red.
- La cuota diaria de análisis (cinco intentos/día local) sigue siendo independiente del rate limit de login.

## Auditoría de código Sandbox — 2026-11-03

**Tipo de evidencia:** revisión estática por agentes más pruebas Chromium con fixtures locales; no es pentest, no visitó destinos públicos y no demuestra controles de red. Las pruebas posteriores ejecutan el pool completo con loopback acotado.

- **DNS/SSRF residual:** el guard valida en preflight; Envoy vuelve a resolver al conectar. `npm run test:egress-rebinding` usa una autoridad DNS sintética que responde dos veces con IP de documentación y luego con canary privado; Envoy deniega, API Sandbox devuelve `502` reintentable, no hay captura ni request al canary. `npm run test:dns-resolver-outage` deja de responder tras esas dos consultas y confirma el mismo fail-closed; `npm run test:proxy-outage` confirma sin fallback directo, `502`, y cero requests/capturas. `sandbox/egress-proxy/tests/topology-boundary.sh` también prueba dos redes Docker aisladas. Estas pruebas son locales/sintéticas, no ACL del host/nube. Envoy CIDR APIs siguen WIP; no son frontera productiva. Hace falta aplicar firewall/kernel/cloud independiente y validarlo en staging; G1-SEC sigue abierto. **Corregido y probado con fixtures:** `isPrivateOrReservedIp` interpreta IPv4-mapped hexadecimal como `::ffff:7f00:1`; `validateDestination` admite resolver inyectable y cubre A/AAAA, mezcla público/privado y fallo DNS fail-closed. No se consultó DNS público ni destino externo.
- **Solicitud secundaria a red privada:** `sandbox/browser-tests/secondary-private-request.browser.ts` navega con Chromium real a un fixture loopback permitido por stubs acotados a su puerto; imagen e iframe solicitan otro puerto loopback usando el guard productivo. El test confirma el bloqueo, señal SSRF y cero solicitudes recibidas por el servidor destino. La suite Chromium corre serialmente (`--test-concurrency=1`): en paralelo, la prueba de deadline de 1 s falló por carga concurrente del browser; aislada y serial pasó. Esto no verifica DNS rebinding, firewall, egress cloud ni red productiva.
- **TLS inválido en subrecurso (ampliado 2026-11-04):** `sandbox/browser-tests/subresource-tls-policy.browser.ts` usa Chromium real, página HTTP loopback e imagen + iframe HTTPS loopback autofirmados; stubs permiten solo esos dos puertos. Caracterización confirmó handshake TCP rechazado antes de HTTP. Tras aprobación del propietario, el pool escucha `requestfailed`, espera `load` y devuelve `inconclusive/tls_certificate_invalid` sin veredicto ni captura. El test verifica ambos tipos de recurso e invariantes. Fallos TLS de requests posteriores a `load` no se ignoran si se observan antes de finalizar la inspección; egress y recursos dinámicos/staging siguen requiriendo QA de alcance mayor.
- **Rutas del navegador:** `context.route('**')` inspecciona HTTP de navegación/subrecursos/redirecciones y `context.routeWebSocket('**')` cuenta y bloquea WebSocket; el contexto configura `serviceWorkers: 'block'`. `sandbox/npm run test:browser` verificó en Chromium real local el límite HTTP/WebSocket y que no ocurre registro de service worker en una fixture loopback. WebRTC/UDP, prefetch y procesos auxiliares todavía hacen imprescindible un firewall egress efectivo. No existe evidencia de política de red o ACL API↔Sandbox↔Mongo.
- **TLS/descargas:** el contexto usa `ignoreHTTPSErrors: false`. El helper clasifica `ERR_CERT_*` tanto en navegación principal como en `requestfailed` de subrecursos; `page.goto` espera `load`. Cualquier error visto produce outcome `inconclusive` con código fijo, sin DOM verdict ni captura. El adaptador API valida la unión y rechaza respuestas inconclusas con veredicto. Pruebas Chromium loopback de documento e imagen prueban pool completo y el flujo API/use-case/UI cubre el estado terminal. No demuestra egress ni sitios públicos, recursos dinámicos posteriores al cierre, archivos temporales/bytes, descargas grandes ni límites de recursos. `acceptDownloads:false` y `download.cancel()` se probaron antes; el callback asíncrono de cancelación no se espera.
- **Límites:** `SANDBOX_ANALYSIS_DEADLINE_MS` default es 25 s (rango 1–28 s), menor que el timeout API default de 30 s. La espera DNS de `dns.lookup` y `saveScreenshot` no se cancelan a nivel de SO/FS: la petición puede devolver 504 al deadline mientras el worker conserva su slot hasta cerrar Chromium y terminar almacenamiento. Esto limita el tiempo de respuesta, no es hard-kill de proceso. La prueba real solo cubre navegación colgada en loopback; DNS real, evaluación, escritura, stress y cleanup cloud siguen pendientes. Tampoco hay presupuesto verificado de requests/bytes/CPU/memoria/disco.
- **Capturas/entrada interna:** Playwright genera WebP; `LocalScreenshotStorage` rechaza PNG y symlinks finales, y no sirve archivos heredados PNG mal etiquetados. La prueba de navegador verifica RIFF/WEBP. La ruta/adaptador aceptan solo UUID y el body/URL tienen límites. El propietario aprobó retención baseline de 30 días con purga diaria; el barrido local con simulación por defecto tiene pruebas de archivos vencidos/recientes, symlinks y nombres inválidos. Falta scheduler, ventana operacional comprobada y revisión de privacidad. El proxy API de captura autenticado y owner-only ya existe, pero `CAPTURE_PROXY_ENABLED=false` y la UI lo oculta hasta verificar red privada API↔Sandbox; no exponer `local://` ni el endpoint Sandbox al cliente.
- **Errores:** la ruta HTTP del Sandbox responde texto genérico y loguea solo `attemptId`; el pool convierte errores Playwright a señales estables (`navigation_failed`, `navigation_timeout`, `ssrf_attempt_blocked`) sin incluir mensaje, URL ni query. Prueba canary sobre el stream real de Fastify verificó que URL/query, bearer, HTML y mensaje de error no aparezcan en respuesta ni logs. La prueba cubre el handler instrumentado; sinks productivos, otras dependencias y retención siguen pendientes.
- **Evidencia positiva limitada:** API↔Sandbox HTTP con Bearer se probó primero con pool sintético; la integración `AnalysisFlowHttp.integration.test.ts` ahora también ejecuta páginas HTTP loopback por API, worker, Sandbox HTTP y Chromium real. Imagen/iframe HTTPS autofirmadas devuelven `inconclusive`, sin captura ni veredicto; MongoDB 8 desechable persiste el estado. Página limpia guarda captura real WebP y el proxy API devuelve sus bytes. La prueba permite solo puertos loopback. Esto no valida certificado/ruta TLS de despliegue, DNS/egress, red privada ni aislamiento. API también probó HTTPS loopback autofirmado con Node fallando cerrado. Ninguno demuestra certificados productivos ni egress.

### Pruebas seguras propuestas

Usar resolver DNS inyectable con respuestas fixtures A/AAAA (pública, mixta, error y rebinding); el TLS principal ahora tiene una prueba del pool completo con fixture autofirmado local y mocks limitados a loopback de prueba. Extender con HTTP/TLS local para redirecciones/subrecursos, cierre/cancelación/deadline/backpressure y límites de archivo; seguir comprobando magic bytes/MIME/IDs en el flujo completo y probar la purga operativa en staging. Completar con prueba en red de contenedores desechable que demuestre que Sandbox no alcanza API, Mongo ni metadata y que API sí alcanza Sandbox. No hacer pruebas de egress contra metadata ni destinos públicos.

Antes de habilitar análisis de Internet o captura: bloquear egress de forma independiente, fijar límites cgroup/backpressure y validar log sinks/retención productivos. Los logs API omiten query, `ProblemDetails.instance` no incluye query y 500 usa allowlist más `requestId`; suites sintéticas cubren la redacción. Esto no certifica sinks de producción ni logs propios de toda dependencia. MIME/retención requieren operación staging. La política TLS estricta y los límites de request/deadline inconclusos están implementados; no declarar una carga incompleta como evidencia de seguridad.

## Verificación de seguridad requerida

Pruebas adversariales de entrada inicial, redirecciones, DNS rebinding, IPv4/IPv6 privado/metadata, subrecursos (iframes, XHR, WebSocket), descargas y TLS inválido; demostrar bloqueo tanto en aplicación como en red egress. Comprobar aislamiento de API/Sandbox/Mongo con políticas de red reales, permisos mínimos, rotación de secretos, acceso cruzado a historial/capturas, abuso de auth y límites de carga. Revisar logs con inspección automatizada para confirmar que URL, contraseña, token y HTML sensible se redactan.

## Gate

No habilitar captura proxy, análisis a Internet pública ni lanzar producción hasta verificar controles de egress/red, identidad entre servicios, permisos/recursos del Sandbox y pruebas adversariales en un entorno de staging aislado. La revisión de seguridad debe registrar amenazas residuales y aceptación explícita.
