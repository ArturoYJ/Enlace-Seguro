## Drain acotado del worker durable — 2026-11-04

- Root cause: `AnalysisJobWorker.stop()` esperaba indefinidamente `Promise.allSettled(inFlight)`, por lo que SIGTERM podía superar el grace period del host aunque el job siguiera recuperable por lease.
- Implementé drain acotado derivado del contrato existente: default API timeout +10 s (40 s), al menos 5 s sobre timeout y siempre menor que lease. El worker deja de reclamar, deja completar poll ya en curso, espera jobs activos; al vencer conserva leases, devuelve `timed_out`, emite warning sin datos sensibles y el proceso cierra DB/HTTP y termina con código no-cero.
- Pruebas nuevas cubren drain normal, claim que termina durante shutdown, timeout preservando recuperación por lease y validación de grace menor que lease.
- Validación: API 71/71 tests, typecheck y build pasan. Suite unitaria de worker 4/4. `npm test` omite integraciones Mongo si no se configura `MONGO_TEST_URI`; tras el cambio, log de `run-mongodb-suite.sh` termina con PASS para integración, explain, matriz, smoke, TTL y dump/restore.
