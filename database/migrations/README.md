# Migraciones

El motor de la actividad es MongoDB. `001_create_mongodb_schema.js` es un bootstrap de una sola aplicación dirigido a una base vacía; crea cinco colecciones, validadores e índices iniciales. **No ejecutarlo contra datos reales**. `002_create_login_rate_limit_buckets.js` agrega la colección de contadores HMAC de login; `003_encrypt_analysis_inputs.js` amplía forward-only el validador de `daily_analyses` para permitir el sobre cifrado de entradas hasta 64 KiB, preservando la lectura de entradas históricas en claro de hasta 8 KiB; `004_durable_analysis_jobs.js` prepara metadatos de cola embebidos, valida leases y crea el índice de reclamación; `005_analysis_queue_capacity.js` agrega el singleton de capacidad, exige el cap operado, preserva el TTL histórico y cuenta jobs pendientes; `006_extend_analysis_history_retention_366_days.js` extiende idempotentemente `historyPurgeAt`/`purgeAt` al baseline aprobado de 366 días, preservando jobs activos sin TTL. La 003 cambia solo validación, no reescribe documentos existentes ni guarda valores en claro nuevos. La 004 inicializa intentos legacy sin URL como fuera de cola y respeta intentos terminales. La 005 requiere detener admisión/workers durante el cutover y debe ejecutarse en replica set compatible con transacciones antes de API. La 006 también requiere detener admisión/workers durante su cutover. No ejecutar 001 de nuevo para incorporar cambios incrementales ni continuar automáticamente ante un estado parcial; inspeccionar y recuperar explícitamente. La suite efímera debe validar las seis migraciones e idempotencia.

Cada script requiere que la persona operadora establezca `globalThis.EnlaceSeguroExpectedDb` y que coincida con la BD actual; rechaza bases de sistema y estado parcial/incompatible. No ejecuta `drop` ni modifica datos existentes. Cambios posteriores deben ir en migraciones incrementales específicas, con revisión de compatibilidad y datos; no editar silenciosamente el bootstrap ya aplicado. El API no crea colecciones/índices al vuelo: requiere migración 002 y falla al validar readiness del rate limiter si el validador estricto o el índice TTL faltan. No mezclar SQL/PostgreSQL con esta secuencia MongoDB.

Ejemplo **solo contra una BD desechable**: aplicar 001, 002, 003 y 004 en invocaciones mongosh separadas, estableciendo `globalThis.EnlaceSeguroExpectedDb` en cada una. `MONGODB_URI` debe apuntar explícitamente a esa base; no guardar credenciales en el repositorio.
